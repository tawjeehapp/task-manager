# UI Design Specification

## Overview

The Work Management Platform follows a modern business application design style.

The interface should feel:

- Professional
- Clean
- Fast
- Organized
- Calm
- Information-focused

The UI should prioritize usability and clarity over visual decoration.

---

# Design Direction

The design language combines:

- Clean productivity software
- Modern SaaS dashboards
- Business information systems

The interface should provide:

- Clear hierarchy
- High information density
- Fast workflows
- Predictable interactions

---

# RTL and Arabic First

Arabic is the primary interface language.

All screens must be designed RTL-first.

RTL requirements:

- Layout direction is right-to-left.
- Navigation starts from the right.
- Text alignment follows Arabic conventions.
- Icons should respect direction.
- Forms should flow naturally.
- Tables should remain readable.
- Dates and numbers should be formatted appropriately.

Do not simply mirror an English layout.

---

# Forms

Forms should follow consistent rules.

Requirements:

- Labels always visible.
- Validation messages below fields.
- Errors should be clear.
- Required fields indicated.
- Submit actions grouped together.

Forms should not use hidden labels.

---

# Tables

Tables are a core part of the application.

Requirements:

- Sorting
- Filtering
- Pagination
- Search
- Column visibility where useful

Tables should support:

- Loading states
- Empty states
- Error states

---

# Cards

Cards are used for:

- Summary information
- Dashboards
- Quick actions

Avoid excessive card usage.

Do not place every element inside a card.

---

# Dashboard Design

Dashboards should be action-oriented.

Avoid:

- Decorative charts
- Vanity metrics

Prefer:

## Summary

Examples:

- Active projects
- Pending approvals
- Overdue tasks
- Team workload

## Action Lists

Examples:

- Tasks requiring attention
- Requests waiting approval

---

# Notifications UI

Notifications should appear through:

- Notification center
- Push notifications
- Optional toast messages

Notification item contains:

- Icon
- Title
- Description
- Time
- Read state

---

# Announcements UI

Announcements should support:

- Priority indicators
- Attachments
- Read status
- Expiry information

Important announcements should be visually distinct.

---

# Loading States

Every async action requires a loading state.

Examples:

- Skeleton loading
- Button loading state
- Table loading state

Avoid blank screens.

---

# Empty States

Every list requires a useful empty state.

Example:

No Projects:

```
لا توجد مشاريع حالياً

ابدأ بإنشاء مشروع جديد
```

Empty states should:

- Explain the situation.
- Suggest the next action.

---

# Confirmation Dialogs

Required for destructive actions.

Example:

Deleting a department:

Show:

- What will be deleted.
- Related records affected.
- Whether action can be undone.

---

# Accessibility

The application should support:

- Keyboard navigation
- Clear focus states
- Proper labels
- Screen readers
- Good contrast

---

# Forms and Data Entry Principles

Prefer:

- Smart defaults
- Minimal required fields
- Clear workflows

Avoid:

- Large complicated forms
- Unnecessary configuration

---

# Animation

Animations should be subtle.

Use animation for:

- Loading
- Transitions
- Feedback

Avoid:

- Decorative animations
- Distracting effects

---

# Icon Usage

Use Lucide icons.

Rules:

- Icons should have clear meaning.
- Avoid unnecessary icons.
- Use tooltips where icons are not obvious.

---

# File Uploads

File uploads should provide:

- Progress indicator
- File preview where possible
- Validation errors
- Size limits

---

# Search

Search should be:

- Fast
- Accessible
- Consistent

Global search should eventually support:

- Employees
- Projects
- Tasks
- Announcements

---

# UI Architecture Rules

## Reuse Components

Common patterns should become reusable components.

Examples:

- DataTable
- PageHeader
- ConfirmDialog
- EmptyState
- StatusBadge
- UserAvatar

---

## Avoid Page-Specific Styling

Pages should compose existing components.

Avoid:

- Large custom CSS files
- Duplicate components
- One-off layouts

---

# Product Feel

Every screen should answer:

1. Where am I?
2. What information matters?
3. What action should I take?

The interface should feel like a professional operational tool.
